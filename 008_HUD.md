# 008 — HUD + End-of-Run Summary

**Status:** Implemented (M4, 2026-06-19) — built, pending dev drive-test (visual). **Refs:** 04_Art_Direction (UI/HUD Philosophy), 02_GDD (Flow/Score).

> **Impl note:** `PlayHUD` (CanvasLayer, built procedurally) — flow ×N.N + colour-shifting bar (cyan→magenta→acid-yellow with level) top-center; score top-right; timer under it; outlined high-contrast text for at-speed readability; flow display dims when idle. End-of-run panel shows final score / time / max-flow + per-event style breakdown / "Press R to restart". Placed top-center+right so the existing `DebugUI` (kept top-left for M4 tuning) doesn't overlap — DebugUI can be removed from the play scene later. **Plan:** `M4_PLAN.md`.

## Play HUD (NEW, CanvasLayer)
The world communicates speed more than the HUD (04). This HUD is for the **play scene** (`Track_Prototype`); keep `DebugOverlay` in the dev/test scenes. Pure observer — reads systems via signals + getters, writes nothing to gameplay.

**Elements:**
- **Flow multiplier** — large, top-center, "in-world-feeling". Reads `FlowSystem.on_changed(value)`; show `×N.N` + a bar that fills with flow. (Full flow-escalation visuals are M5; prototype = number + bar, optional color shift with level.)
- **Score** — small, top corner. Reads `ScoreSystem.on_score_changed(score)`.
- **Timer** — small, top corner. Reads the RunManager timer.
- Speedometer — optional; speed is already felt via FOV. Skip or keep tiny.

**Style (04):** flat, high-contrast, graffiti-inflected typography; no racing-game chrome; HUD elements **fade when not actively changing**.

## End-of-Run Summary (NEW panel)
On `RunManager.on_run_finished(score, time)`: show a panel with:
- **Final score** (large)
- **Time**
- **Flow / style breakdown** — max flow reached + per-event style points from `ScoreSystem.get_style_breakdown()`
- **Restart** prompt (restart is always available; returns to a fresh run)

Minimal styling for the prototype.

## Architecture
Lives in the play scene. Connects to `FlowSystem`, `ScoreSystem`, and `RunManager` signals in `_ready`. Reads getters per-frame for the timer. No coupling back into physics/camera.

## Exit
During a run the player sees the Flow multiplier respond to their skill and the score climb; on finish, a summary shows the result and invites a restart. Readable at speed — it must **never obscure the track** (04 hard rule: "visual feedback that makes movement harder to read" is unacceptable even at prototype).
